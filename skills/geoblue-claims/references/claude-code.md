# Claude Code with Playwright MCP

Open Claude Code from the repository root. The link at `.claude/skills/geoblue-claims` registers `/geoblue-claims`. The project `.mcp.json` starts `geoblue_playwright`, a local Microsoft Playwright MCP server pinned to `@playwright/mcp@0.0.86`.

The browser setup needs Node.js 18 or later, `npx` or `pnpm`, and Google Chrome. Approve the project MCP server in Claude Code and check its connection with `claude mcp get geoblue_playwright`. The server starts a dedicated Chrome profile in the local browser cache. Sign in to GeoBlue yourself in that window, including any verification challenge. Reuse the same browser session for the claim. Keep downloaded evidence and screenshots in private `data/` and give files explicit paths under that directory. Do not copy credentials, storage state, or full banking details into the project.

## Preparation

Use the same intake, review, entry authorization, and final confirmation as the parent skill. Follow the observed wizard stages in [fast-path.md](fast-path.md). Use the `geoblue_playwright` tools in Claude Code instead of importing the Codex helper.

1. Use `browser_snapshot` for live controls and `browser_click` with current refs. After a navigation, popup, or selection, use the new action result or snapshot. Wait for visible loaders to clear. Confirm the official HTTPS origin before sending any claim data. From the eClaims list, open the exact matching unsubmitted card with **Continue** or **details**, depending on layout. Check that the resulting `q` reference matches the saved draft. A first-time introduction can be dismissed with **Skip**.
2. Preserve existing contact details and choose the authorized patient and insurance answers. Fill charges from the entry-guard snapshot. The portal uses Flutter. Clicking **Next** or **Upload document** by an offscreen semantic ref can focus it without performing the action. Use a real wheel scroll and a fresh screenshot to locate the rendered button, then click it at its visible coordinates using the MCP vision tools. For text, click the rendered input, select existing text with `browser_press_key`, then type with `browser_type` and `slowly: true` if a fill does not commit. In the live rehearsal, native Playwright mouse and keyboard actions through MCP saved an edit that a semantic fill did not commit. Verify the saved values before continuing. Do not reuse coordinates from another viewport or form state.
3. Verify the exact approved attachment bytes and paths from `draft entry-guard`. Open **Add Supporting Documents**, click the visible **Upload document**, and wait for MCP to report **File chooser**. Call `browser_file_upload` with the exact absolute path, one file per chooser. Wait for the saved charge page and verify the filename. The tested portal advertised PDF, PNG, JPG, and JPEG with a 10 MB limit. Check the current page for its requirements. On resume use the stored upload record and hash before treating an existing file as complete. Reconcile an uncertain upload before retrying.
4. Select the verified saved masked payout option. Continue to Authorization and capture the review evidence. Leave the certification unchecked and the name blank. Present the final review and wait for the user's confirmation in chat.

## Test a saved draft

Use only an explicitly authorized, existing draft whose exact eClaim ID is listed under **Unsubmitted eClaims** and whose nickname marks it as a test. Recheck the same ID before each mutation. A test can exercise an existing charge and a new authorized test attachment. Keep existing receipts and do not create duplicate charge rows or upload an existing file twice. Use a clearly named synthetic file without patient data if a dedicated upload probe is needed and authorized. Stop at Authorization with the checkbox unchecked and signature blank. **Never invoke the final Submit action, certify, sign, run `draft approve`, or start a submission attempt in a test.** A TEST draft never becomes a production application.

Check the live origin, draft ID, real claim identity, and final snapshot. Use the actual declaration and authorized signer.
